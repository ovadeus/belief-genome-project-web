# Overview

This project is a full-stack website for the "Belief Genome Project," a psychometric self-knowledge framework, which also includes a desktop application and a book. The platform aims to provide users with tools to map and understand their beliefs through an interactive system, while also offering public resources like a blog and information about the project. The business vision is to establish a leading platform for psychometric self-discovery, leveraging a unique belief-mapping framework to foster self-awareness and personal growth. The project ambitiously seeks to expand into a comprehensive ecosystem including web, desktop, and print media, targeting individuals seeking deeper self-understanding and researchers in psychology and sociology.

# System Architecture

The project utilizes a pnpm workspace monorepo with TypeScript, Node.js 24, and pnpm. The monorepo is structured into `artifacts` (deployable applications: `api-server`, `whoo-ru` frontend, `genome-app`, and `mockup-sandbox`) and `lib` (shared libraries such as `api-spec`, `api-client-react`, `api-zod`, `db`, and `belief-engine`).

**Note on Entropy Harvester:** The Entropy Harvester product (beliefmetrics.com) was previously incubated in this repo as `artifacts/entropy-harvester` with backend routes under `/api/eh/*` and `eh_*` Drizzle tables. As of April 27 2026 it has been forked into its own standalone Replit project so it can publish independently to beliefmetrics.com. All EH source code, OpenAPI paths/schemas, generated client hooks, backend routes (`/api/eh/*`), middleware (`ehAuth.ts`), Stripe lib (`ehStripe.ts`), and the Drizzle schema file (`lib/db/src/schema/eh.ts`) have been removed from this repo. **Orphaned data:** the `eh_orgs`, `eh_users`, `eh_subscriptions`, and `eh_audit_log` tables still exist in this Postgres database but are no longer referenced — they can be dropped manually if desired. The EH-specific environment variables (`EH_JWT_SECRET`, `STRIPE_SECRET_KEY`, `STRIPE_PRICE_ID_*`) are also unused here and can be removed from this Repl's secrets vault.

Trigger is intentionally undocumented for social-media discovery: type the letters `B → G → P` in sequence within ~1.2 seconds anywhere on the dashboard (suppressed inside form inputs, with modifier keys held, or during IME composition). Toggles play/stop. Audio engine in `genome-app/src/lib/harmonize/` is React-free for desktop port reuse: `harmonizer.ts` (orchestration), `musicbox-synth.ts` (signal chain), `bed-arrangement.ts` (DNA-derived chord progression), `reverb-ir.ts` (synthesized hall impulse for ConvolverNode — no audio assets shipped), `sequence.ts` + `pitch-map.ts` (per-cell C-major-pentatonic notes). Layered playback: a slow chord pad bed whose mode (Lydian / Ionian / Aeolian) is picked from the user's global belief centroid and whose chord per region is driven by each category's confidence-weighted average score, with per-cell triangle+sine notes layered on top as "sparkle." A dedicated `bedDuck` gain stage sidechains the bed under each note onset (~250ms dip) without colliding with the bed's long-form fade automation. Adjacent bed regions truly crossfade by overlapping in time. Two stop profiles: `'user'` (~800ms gentle fade on toggle-off) and `'natural'` (~1.2s bed ease + ~2s reverb tail at end of sequence). Total runtime ~24-32s for 124 cells at `cellMs=240`. React adapter `hooks/use-harmonize.ts`; key-sequence detector `hooks/use-bgp-easter-egg.ts`; component-level toggle wired via window `CustomEvent('bgp:harmonize-toggle')` so DnaStrip stays decoupled from the trigger.
*   **Belief Engine (`@belief-genome/engine`):** A pure TypeScript domain logic package defining the 128-dimension framework, probe bank, DNA string calculation, and DNA prefix structure. It also includes `probeFeeds.ts` for AI-classified belief probes from RSS feeds.
    *   **DNA Signature Codec (V2.1, Apr 30 2026):** `dnaSignature.ts` is the single source of truth for share signatures and `.bgp` files. It speaks **two formats** so old links/files keep working:
        *   **V1** — legacy. 124-char belief segment (one `[0-9·]` amplitude per dimension), 140-char full DNA (16-char demographic prefix + 124-char segment, no separator).
        *   **V2** — current desktop spec. 248-char belief segment (alternating `[0-9·][A-E·]` for amplitude+coherence per dimension, A=lowest…E=highest coherence), 265-char full DNA (16-char prefix + `-` + 248-char segment).
        *   **Checksum** — switched from FNV-1a to **SHA-256** (first 16 bits → base36, padded to 4 chars) so signatures are byte-identical to the desktop side. All codec entry points (`encodeAnonymous`, `encodeSigned`, `decodeSignature`, `parseSignatureFromAnyInput`, `buildBgpFile`, `parseBgpFile`) are **async** because `crypto.subtle.digest` is async. Signatures are minted in V2 by default; both formats are accepted on read. `.bgp` files write `format: 'bgp-dna/v2'` by default and accept both versions.
        *   `DecodedSignature` exposes `version: 1|2`, `amplitudes: number[]` (length 128, the per-dimension 0–9 scores, with `null` for `·`), `coherence: (string|null)[]` (V2-only A–E or `null`), `demographicPrefix`, plus the legacy `beliefSegment` raw string for back-compat. Consumers should read scores from `amplitudes`, not by indexing the raw segment.
        *   DB columns `known_dnas.signature`, `dna_share_events.signature`, `dna_share_events.signature_b` are `varchar(280)` (V2 signed sigs run ~272 chars; 280 leaves headroom).
        *   **Checksum migration (Apr 30 2026):** `scripts/migrate-checksums-to-sha256.ts` re-stamped all stored signatures (3 pre-cutover rows in `dna_share_events`; `known_dnas` was empty) so old V1 share links continue to validate after the FNV→SHA-256 switch. The script imports the engine's `checksum()` directly so there's one source of truth, and handles `signature` + `signature_b` on `dna_share_events`. Re-runnable safely (idempotent — already-correct rows count as `unchanged`). Run via `pnpm --filter @workspace/scripts run migrate:checksums:dry` then `…run migrate:checksums`.
        *   Tests: `lib/belief-engine/test/dnaSignature.test.ts` (run via `pnpm --filter @belief-genome/engine run test` — node:test + tsx). 11 cases cover V1+V2 anon/signed round-trip, tamper rejection, SHA-256 ↔ desktop parity, raw-paste detection (V1 140-char, V2 265-char, V2 segment with `·`), and `.bgp` v1+v2 round-trip.
        *   **V2 minting (Apr 30 2026, Full ship):** The web now mints V2 DNA strings end-to-end with **per-dimension coherence A–E** (was V1 only — desktop was already V2). Coherence semantics: *how internally consistent the user's answers within that dimension have been* — not the same as confidence (which measures evidence amount). Scale: E=most settled (std<0.10 on the directed-and-weighted answer space), D<0.20, C<0.32, B<0.45, A=most internally conflicted. **Floored to `·` (unknown) when count<3** so single-response dims don't masquerade as "perfectly settled." Implementation:
            *   `dimension_scores.sum_squares` (real, default 0, NOT NULL) added to track Σ(directed²·effective_weight) per dim. Variance derived as `sumSquares/totalWeight − (sum/totalWeight)²`. Stale-row guard (see Engine bullet below) prevents pre-V2 rows from emitting spurious 'E', so it's safe to deploy the schema before the back-fill runs.
            *   Engine: `Accumulator` widened with `sumSquares: number`. Both `updateDimensionScores` and `applyResponseToScores` accumulate it. New `calcCoherence(accum)` returns 'A'..'E' or null. Stale-row protection uses `sumSquares===0 && sum!==0` as the unmigrated marker (any genuine accumulation of non-zero directed values produces sumSquares>0); rows where `sum===0 && sumSquares===0` are treated as legitimately settled at neutral and emit 'E'. Negative variance from FP cancellation is clamped to 0 so near-identical answers map to std=0 → 'E' rather than NaN. `buildDNAString(dimScores, userMeta?, coherence?)` defaults to V2 (16+`-`+248=265 chars) — `coherence` may be omitted (all-`·`) and the string is still structurally valid V2. Explicit `buildDNAStringV1` retained for tests / narrow back-compat.
            *   Production write paths (3 sites — `genome-data.ts:upsert`, `genome-data.ts:tx`, `genome-probes.ts:tx`) all persist `sumSquares: acc.sumSquares`. Production read paths (4 buildDNAString callers + 4 ancillary Accumulator constructors in `genome-data.ts`/`genome-compare.ts`) all SELECT `sum_squares` and the buildDNAString callers compute + pass a coherence map.
            *   Back-fill: `scripts/backfill-sum-squares.ts` — replays each user's belief_responses through the canonical `applyResponseToScores` (same code path as live ingest, so result is bit-identical) and UPDATEs only `sum_squares`, never the score fields. Idempotent (skips rows already within float epsilon). Run via `pnpm --filter @workspace/scripts run backfill:sumsq:dry` then `…run backfill:sumsq`. Initial run on Apr 30 2026 touched 15 rows across 2 users (other rows had count<3 or all-mid-slider answers, both of which produce variance=0 → still emits 'E' for the truly-settled mid-slider case via the stale-row guard's `sum!==0` carve-out). Operational note: the back-fill is not snapshot-isolated; if a `/respond` lands during the run, that response's contribution to `sum_squares` may be silently overwritten. Re-run the back-fill once after the deploy quiet period to reconcile any drift.
            *   Canonical `/analyze` rebuild: previously this route used a bespoke unweighted formula that would drift persisted `weighted_sum`/`total_weight`/`sum_squares` away from the live ingest math (no quality-weight multiplier). Now it replays responses through `applyResponseToScores`, so a `POST /analyze` after live activity preserves bit-identical accumulators.
            *   Downstream: the `genome-submit.ts` slice `dnaString.slice(16)` was V2-aware'd to `slice(17)` and walks amplitudes by stride 2 (since the segment now interleaves `[amp][coh]`). `genomeSubmissions.beliefValues` JSON shape unchanged — still amplitude-only by dim id.
            *   Tests: `lib/belief-engine/test/dnaCalculator.test.ts` — 9 new cases covering the count<3 null floor, identical-response → 'E', maximally-split → 'A', stale-row guard (`sum≠0 && ss=0` → null), settled-at-neutral carve-out (`sum=0 && ss=0` → 'E'), monotonic A→E ladder, V2 emit shape (`/^([0-9·][A-E·]){124}$/`), V1 helper still emits 140 chars, and full rebuildDNA → encodeAnonymous → decodeSignature round-trip with coherence preserved. Total engine tests: 21 passing.
        *   **Coherence realignment to phase-residual (May 1 2026):** The web's user-facing coherence letter now matches the desktop / Frontiers paper canonically — *phase residual within framing pairs*, not std-based answer scatter. **A↔E semantics flipped**: `A = most coherent` (lowest |φ| — answers mirror their twin), `E = least coherent` (anti-mirror / contradiction), `·` when no completed framing pair exists for the dimension. The realignment is end-to-end:
            *   Probe bank: the validated 1488-probe V2 bank (124 dims, 6 pairs/dim, IDs 4–127) is mirrored into the engine at `lib/belief-engine/src/probeBankV2.json`. The matching A–E cutoffs live at `lib/belief-engine/src/coherenceCutoffs.json` (placeholder equal-bins on `[0, π]`; will be replaced after empirical calibration without a code change). Loader at `probeBankV2.ts` runs all 4 spec invariants on import (1488 probes, 124 dims with 12 probes each, 744 pairs each with one canonical + one inverted, no orphan partner refs) and throws if violated.
            *   Engine: new `calcPhaseEstimates(responses)` mirrors the desktop's atan2 algorithm verbatim (per dim: `φ = atan2(Σ(r_C − r_I_flipped)·loading, Σ(r_C + r_I_flipped)·loading)` over completed pairs only). `gradeCoherence(phase, {dimId})` maps |φ| → A–E via the cutoff config. `buildCoherenceMap(history)` is the convenience wrapper used by both `rebuildDNA` and the API mint paths. The std-based `calcCoherence` is **retained as an internal QC metric** ("answer scatter / response variance") but is no longer imported in any path that emits a DNA signature; its docstring was updated to reflect that role.
            *   Schema: `probe_v2 jsonb` added to BOTH `belief_responses` (so V2 metadata survives the ingest hop) and `probes` (so the queue carries the metadata from refill time through delivery). Applied via raw `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` to preserve the orphan `eh_*` tables that `db push` would have dropped — same pattern used for `sum_squares`. The schema also defines a narrow `ProbeV2Persisted` type so the `.$type<>()` brand surfaces real autocomplete on the column.
            *   Queue + ingest: `refillBank` in `genome-probes.ts` was rewritten to draw from `PROBE_BANK_V2` instead of the legacy hand-curated bank, persisting `probeV2` on every queued row. `/next` echoes `probeV2` to the client; `/respond` resolves it via (client body → queued row lookup → bank text match) and writes it onto the `belief_responses` row in the same transaction as the score update. The legacy `PROBE_BANK` and the news feed remain available as fallbacks (their rows have `probe_v2 = null` and contribute amplitude only — phase recovery skips them, which is correct per spec).
            *   Mint sites: all 4 `buildDNAString` callers in `genome-data.ts` (`/dna`, `/analyze`, `/timeline`, `/submit-public`) now compute coherence from `buildCoherenceMap(history)` instead of `calcCoherence(accum)`. Dimensions with a value but no completed V2 pair fall back to `·` so the serial stays structurally valid. `dimension_scores.sum_squares` is still populated by the engine accumulator path — kept as internal answer-scatter QC, not surfaced as the coherence letter.
            *   Back-fill: `scripts/backfill-probe-v2.ts` (commands `backfill:probev2:dry` / `backfill:probev2`) populates `belief_responses.probe_v2` and `probes.probe_v2` by exact text match against the V2 bank. Idempotent. As expected per spec, the legacy bank texts have **zero overlap** with V2, so legacy historical responses keep `probe_v2 = null` and continue to contribute amplitude only — coherence will populate organically as users answer V2 probes.
            *   One-shot DB cleanup: 579 undelivered legacy queue rows (`delivered=false AND probe_v2 IS NULL`) were deleted so `refillBank` could reach its 15-row threshold and start queuing V2 probes immediately rather than after users drained the legacy backlog. The 36 already-delivered legacy rows remain as historical record. Smoke test confirmed: after the flush, `/next` started returning V2 probes with full framing-pair metadata and `/respond` round-trips the metadata to `belief_responses` (verified count went 0 → 1).
            *   Prod migration: `scripts/migrate-add-probe-v2-columns.ts` (commands `migrate:probev2:dry` / `migrate:probev2`) codifies the raw `ALTER TABLE … ADD COLUMN IF NOT EXISTS "probe_v2" jsonb` for both `belief_responses` and `probes`. Idempotent (information_schema check + `IF NOT EXISTS`), so it's safe to wire into a deploy hook or run by hand. Ops note: the same hand-rolled pattern was used for `sum_squares` because `db push` would drop the orphan `eh_*` tables.
            *   Determinism hardening: the 3 mint-path queries that feed `buildCoherenceMap` now all `.orderBy(beliefResponses.createdAt, beliefResponses.id)`. Without this, addition inside `calcPhaseEstimates` is order-invariant for the φ value itself, but pair-completion detection picks the first canonical+inverted match it sees — so if a user has duplicate responses for the same probe (the unique constraint is on `(user_id, client_id)`, not on probe text), pair selection could flip across re-mints. The added (createdAt, id) tie-break makes the public signature bit-stable across re-mints in that edge case.
            *   Tests: `dnaCalculator.test.ts` rewritten — removed obsolete std-based ladder/E-for-identical assertions (the meaning of A and E flipped), added the 4 spec edge cases (`·` when no completed pair, `A` for perfect mirror 0.9/0.1, `C` for agree-everything 1.0/1.0, `C/D/E` for asymmetric anti-mirror — single-pair max |φ| is π/2 which lands in C under the placeholder cutoffs), the cross-platform parity fixture (3 mirror pairs at 0.9/0.1 → φ=0, magnitude=0.8 — note the spec doc claimed magnitude=1.0, that's a doc bug; magnitude only saturates at 1.0/0.0 inputs), and the V2 round-trip test now uses real V2 probe metadata. The std-based `calcCoherence` keeps a tiny smoke test confirming QC pages still get a letter. Total engine tests: 22 passing.
